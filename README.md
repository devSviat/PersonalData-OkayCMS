# Згода на обробку персональних даних для OkayCMS

Модуль працює лише на форку OkayCMS: https://github.com/devSviat/OkayCMS-Fork. На стоку 4.5.3 він не підтримується.

Модуль додає чекбокс згоди у форми, що збирають персональні дані: кошик, реєстрацію, зворотний
зв'язок, замовлення дзвінка, коментарі, «Купити в один клік» і форми інших модулів, які підключили
фасад. Сервер вимагає позначку лише тоді, коли сам показав чекбокс у цій сесії.

Кожну згоду модуль записує в журнал: форма, запис, час, мова, сторінка політики. IP зберігається
тільки тоді, коли сам запис його не містить. Підпис чекбокса береться з мовних файлів, а його кінець
веде на сторінку політики, вибрану в налаштуваннях модуля.

## Адмінка

- «Форми»: перемикачі для кожної форми й картка «Налаштування».
- «Журнал»: фільтри, експорт у CSV, відкликання й знеособлення згод.

Коли запис видаляють, його згода знеособлюється. Знеособлені згоди видаляються після строку
зберігання.

## Вимоги

- [Форк OkayCMS](https://github.com/devSviat/OkayCMS-Fork);
- PHP 8.5;
- планувальник OkayCMS у cron: він видаляє згоди, строк зберігання яких минув.

## Встановлення

1. Завантажте архів з [останнього релізу](https://github.com/devSviat/PersonalData-OkayCMS/releases/latest)
   і розпакуйте його в `Okay/Modules/`. Має з'явитися каталог `Okay/Modules/Sviat/PersonalData`.
2. «Модулі» → «Мої модулі»: встановіть і увімкніть PersonalData.
3. Натисніть «Оновити» біля модуля в списку модулів. Поки цього не зроблено, згода ніде не діє.
4. Відкрийте сторінку модуля, виберіть сторінку політики й позначте форми.

## Оновлення з 1.0.x

Розпакуйте архів нової версії поверх старої й натисніть «Оновити» біля модуля. Оновлення створює
таблицю журналу, переносить перемикачі форм зі старих налаштувань `pd_*` і чистить `compiled/`.
Доки «Оновити» не натиснуто, згода не діє ніде: чекбокс не малюється, а в адмінці модуля висить
банер з нагадуванням.

## Як підключити форму свого модуля

1. Перед кнопкою відправки надрукуйте блок дизайну:

   ```smarty
   {get_design_block block="sviat_personal_data_<форма>"}
   ```

2. Після власних перевірок і до збереження викличте `Integration\Consent::check('<форма>')`.
   Рядок у відповіді є текстом помилки для форми, `null` означає, що можна зберігати.
3. Після створення запису викличте `Integration\Consent::link('<форма>', $id)`.

Фасад викликайте лише тоді, коли клас існує й модуль активний. Без PersonalData блок порожній, а
форма працює як раніше. Саму форму треба описати в реєстрі `Init/services.php` цього модуля.

## Тести

Тести лежать у `tests/` і в архів релізу не потрапляють. Щоб їх запустити, покладіть модуль і тести
у форк:

```
{OkayCMS_root}/
├── Okay/Modules/Sviat/PersonalData/
└── tests/Modules/Sviat/PersonalData/
```

```bash
cd {OkayCMS_root}
vendor/bin/phpunit --display-skipped tests/Modules/Sviat/PersonalData
```

Частина тестів перевіряє зв'язку з іншими модулями. Якщо такого модуля в системі немає, тест
пропускається й пояснює чому, тому кількість пропущених видно у звіті PHPUnit.

CI на кожен PR перевіряє синтаксис під PHP 8.5, запускає тести у форку й окремо перевіряє анкери
чекбокса в кожній темі форку. Після мерджу в `main`, якщо версії з `Init/module.json` ще немає
серед тегів, CI ставить тег і публікує реліз з архівом.
